OBO 本体下载与实体映射

2026-05-05：为替代 UMLS API，下载 OBO Foundry 本体并完成知识图谱实体-本体 ID 映射
最后更新: 2026-05-05

1. 🎯 背景

UMLS API Key 尚未获得审批，需要零成本替代方案建立知识图谱实体的标准化生物医学 ID 映射。选用 OBO Foundry 本体，通过名称匹配将 KG 实体映射到标准本体标识符。

3. 🔗 实体映射结果

3.1 映射方法

基于名称匹配（含同义词匹配），不使用 API，纯本地解析：

  1. 疾病 → DOID: 通过疾病名称（中英文）与 DOID 标签/同义词匹配
  2. 症状 → HP: 通过症状名称与 HP 标签模糊匹配
  3. MONDO → DOID 桥接: 通过 MONDO 的 hasDbXref 字段提取 DOID 引用
  4. MeSH → DOID 桥接: 通过关系中的 mesh_ui 属性 + MONDO 的 MESH→DOID 映射
  5. 手动策展: 对关键中文疾病名和癌症类型手动修正

3.4 MeSH → DOID 桥接技术细节

  • KG 中的 MeSH 实体 ID 格式为 MESH_EnglishName（如 MESH_Portasystemic_Shunt_Surgical）
  • 但关系类型的 has_mesh 在其 attributes.mesh_ui 中包含标准 MeSH UI（如 D006801）
  • MONDO 的 hasDbXref 使用 MESH:D006801 格式（注意：MONDO 使用 MESH: 前缀，不是 MSH:）
  • 映射链路: KG 关系 mesh_ui → MONDO hasDbXref → DOID
  • 结果: 4,848 个 unique mesh_ui 中有 280 个映射到 DOID

3.5 未匹配原因

  • 中文疾病名称（如”肝源性肾损害”）在 DOID 中无直接对应——DOID 主要是英文
  • 部分占位符实体（如 DISEASE_2f9b5e21）无实际疾病名称
  • 复合症状（如”Posterior Leukoencephalopathy Syndrome”）在 HP 中匹配为解剖结构而非表型
  • 药物实体: 7 个药物均为 hash ID（如 DRUG_09606a77），无有意义名称无法匹配 CHEBI
