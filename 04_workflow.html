跨源数据关联分析 (Cross-Source Mapping)

更新于 2026-04-27 21:17

背景

统一数据标准化后，各数据源在 Unified JSON 中仅实现了”同一个文件里的合并”，并未做真正的实体对齐。 需要验证不同来源的数据是否真的有关系连接。

已完成的桥接

桥接ID名称匹配数方法置信度
BRIDGE_001KG_Merge ↔ CM3KG (疾病名)43精确中文名匹配高
BRIDGE_002ChEMBL target_uniprot ↔ UniProt Entry1,165/1,917 (61%)直接 ID 匹配高
BRIDGE_003KG_Merge 疾病子图7 实体 + 84 关系基于 BRIDGE_001高
BRIDGE_004ChEMBL → PubChem CID100 样本 100%PubChem REST API高（限流中）
BRIDGE_005PubChem CID → STITCH50% 样本命中CIDs{N:08d} 格式映射高

未打通的桥接

桥接原因方案
KG_Merge → MONDO中文→英文疾病名需 UMLS 翻译
KG_Merge → ChEMBL药物为占位符 ID需回溯原始数据
STITCH → UniProt缺蛋白质 ID 字段需 STITCH 蛋白数据
CM3KG → MONDO中文→英文疾病名需 UMLS 翻译

关键发现

  • Unified JSON 的 930K 关系中，仅 2,777 条 (< 0.3%) 是跨源连接（全部是 OBO 本体之间）
  • 数据集之间的真实连接 极少，大部分数据仍需额外映射工作
  • 唯一完整的可追溯路径（经验证）：KG_Merge 疾病名 → CM3KG 疾病名 →（待 UMLS）→ MONDO → OBO 本体链
