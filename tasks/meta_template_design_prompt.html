任务：设计第一条 Layer 1 Meta-Template（元模板）

此任务属于肝病知识图谱项目 — 证据链推理引擎（方向三） 的一部分。 请阅读以下完整背景，然后完成具体任务。

一、项目背景（必读）

本项目是一个生物医学知识图谱项目，核心命题是弥合知识图谱构建者与使用者之间的认知鸿沟。

三大方法贡献：

  1. 临床场景层（✅ 设计完成）— 把图谱的”网络结构”翻译成医生能理解的”场景化知识”
  2. 跨模态语义对齐（🚧 待实现）— 多源数据语义颗粒度差异的对齐与融合
  3. 证据链推理（🧪 当前任务）— 把图谱输出的”关系”变成可追踪的”推理路径”

三者关系：跨模态对齐为底层（数据怎么融）→ 场景层为桥梁（需求怎么接）→ 证据链为上层（结果怎么用）。

二、证据链推理引擎的核心设计（必读）

2.1 架构定位

知识图谱和证据链推理引擎是两个独立的系统。

  • 知识图谱：负责存储和组织知识（实体-关系网络）
  • 证据链引擎：负责推理（从证据到结论的路径追踪）
  • 知识图谱只是推理引擎的多个数据源之一（与 PubMed 文献、临床数据并列）

2.2 三层模板架构

已确定的方案（Kimi 分析建议 + 项目组确认）：

层级粒度职责示例
Layer 1: Meta-Template粗粒度定义推理拓扑 DAG，跨疾病通用症状→候选疾病→证据验证→结论
Layer 2: Domain Template中粒度某类疾病的参数化配置，通过领域插件加载HCC 诊断配置（AFP cutoff、影像规则）
Layer 3: Instance Template细粒度运行时动态绑定，图谱查询实例化具体患者的诊断链

核心原则：

  • 模板不携带领域事实 → 领域事实由知识图谱动态供给
  • 推理拓扑与领域知识分离 → 模板只引导推理方向
  • 运行时动态绑定 → 通过插件机制实现模板到实例的绑定

2.3 四种推理模式（已识别）

  1. 演绎推理：前提 → 事实 → 结论（如”所有 HCC 中 70% AFP 升高，该患者 AFP 升高 → 可能 HCC”）
  2. 溯因推理：观察 → 候选解释 → 最优选择（如”AFP 升高 + 超声结节 → HCC？ICC？肝腺瘤？”）
  3. 类比推理：已知模式 → 新场景映射（如”索拉非尼抑制 VEGFR 对 HCC 有效 → 类似结构的新药也可能有效”）
  4. 时序推理：事件序列 → 因果关系推断（如”HCV 感染 → 肝硬化 → HCC”）

2.4 证据类型

证据类型来源可信度
文献证据PubMed高（经同行评议）
本体证据HepatoOntology高（专家定义）
关联证据CTD / DisGeNET中（统计关联）
临床证据临床数据集高（真实数据）

2.5 证据链引擎的完整流程

用户查询 → 场景解析器识别场景类型
         → 选择 Layer 1 元模板（根据场景类型）
         → 加载领域插件，绑定 Layer 2 领域模板
         → 领域插件向知识图谱发送查询，获取 Layer 3 实例数据
         → 模板实例化，填充推理路径
         → 每一步从图谱/文献/临床数据收集证据
         → 证据融合评估（质量×权重×时效性）
         → 生成可解释性输出（带引用和置信度的推理报告）

2.6 肝病知识图谱当前数据概况

  • 实体：31,447 个（7 种类型：疾病、症状、药物、基因、蛋白、MeSH、文献）
  • 关系：98,605 条
  • 疾病→DOID：84.5% 已映射
  • 症状→HP：73.9% 已映射
  • 主要关系类型：has_mesh（文献-MeSH关联）、has_literature（实体-文献关联）、has_symptom（疾病-症状关联）、treated_by（疾病-药物关联）

三、当前任务：设计第一条 Layer 1 Meta-Template

3.1 任务目标

设计一条诊断推理元模板（Diagnostic Reasoning Meta-Template） 的 DAG 拓扑结构。

这是证据链引擎的基石——它定义了推理路径的骨架，后续所有肝病诊断场景的推理都将基于这个元模板实例化。

3.2 需要产出

请给出一个结构化的元模板定义，至少包含以下内容：

A. 模板标识与描述

  • 模板名称（如 DiagnosticAbduction）
  • 适用范围（适用于什么类型的推理场景）
  • 一句话描述

B. DAG 拓扑结构

定义推理路径的节点和边，包括：

  • 节点列表：每个节点的类型、输入、输出、功能描述
  • 边列表：节点之间的连接关系和条件
  • 分支/分支逻辑：如果存在条件分支（如”如果证据充分则走 A 路径，否则走 B 路径”）

请用以下格式描述 DAG：

节点1 → 节点2 → [分支]
                ├→ 节点3a → 节点4a
                └→ 节点3b → 节点4b

C. 每个节点的槽位（Slot）定义

元模板中的每个节点需要声明它需要从外部获取哪些信息。这些槽位是模板与”领域事实”之间的接口。

例如：

D. 推理模式的嵌入

这个元模板应该支持哪些推理模式？（从 §2.3 的四种模式中选择）

  • 每个推理模式在 DAG 的哪个节点/路径被激活？
  • 不同的推理模式如何协同？
  • 如果用户查询触发多种推理模式，如何组织输出顺序？

E. 输出结构

推理完成后，期望的输出格式（结构化推理报告）应该包含哪些字段？

例如：

F. 边界条件与特殊处理

  • 证据数量不足时怎么办？
  • 不同来源证据矛盾时怎么办？
  • 用户输入信息不完整时怎么办？

G. 与知识图谱的交互接口

元模板中的哪些步骤需要查询知识图谱？

  • 每个查询需要什么输入？
  • 期望从图谱返回什么结构的数据？
  • 如果图谱没有返回结果怎么办？

3.3 参考示例：一个简化的诊断推理元模板 DAG

[用户输入]
    ↓
[症状/观察解析] → 提取关键临床特征
    ↓
[候选疾病生成] → 基于症状匹配可能的疾病列表
    ↓
[证据收集] ───── 为每个候选疾病搜索支持/反对证据
    ↓
[证据评估] ───── 评估证据质量、权重、时效性、一致性
    ↓
[推理引擎] ───── 综合评估，生成各候选疾病的置信度
    ↓
[结论排序] ───── 按置信度排序，输出鉴别诊断列表
    ↓
[可解释输出] ──── 生成带证据链和不确定性说明的推理报告

3.4 需要特别注意的设计原则

  1. 模板不携带领域事实：任何具体数值（如 “AFP > 400 ng/mL”）、具体疾病名称（如 “HCC”）、具体规则（如 “LI-RADS 分类”）都不应出现在元模板中。这些应该由 Layer 2 领域配置和 Layer 3 图谱数据提供。
  2. 推理拓扑与领域知识分离：元模板只定义”怎么推”，不定义”推什么”。
  3. 通用性：这条元模板应该能适用于肝病领域内的所有诊断场景，甚至可能扩展到其他疾病领域。
  4. 可组合性：元模板应该支持与其他元模板（如治疗推理、预后评估）组合使用。

3.5 输出格式

请以结构化的 Markdown 文档输出，包含上述 A-G 所有部分。如果能提供 YAML/JSON Schema 形式的元模板定义，将非常有帮助。
