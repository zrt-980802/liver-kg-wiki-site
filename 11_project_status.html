3. 🔴 待办任务（按优先级）

✅ P0：中文疾病名补充映射

  • 状态: 📋 映射建议已生成（12_manual_doid_mapping.md），等待确认后写回
  • 范围: 48 个中文疾病名需要手工 DOID 映射
  • 已确认映射: 22 个通过 DOID 验证（见 12_manual_doid_mapping.md §2.1）
  • 待确认: 18 个需要人工判断精确 DOID（见 §2.2）
  • 占位符跳过: 5 个无有意义名称的 hash ID 实体
  • 非 CM3KG 补充: 6 个英文疾病实体需要赋值（如 Budd-Chiari, HCC 等）
  • 下一步: Andong 确认映射 → 写回 enriched_entities.json

P0：药物 hash ID 溯源

  • 目标: 7 个药物实体（DRUG_09606a77 等）从图中找到实际药物名
  • 方法: 检查与这些实体关联的 treated_by 关系（目前 0 条），或在 PubMed 文献/MeSH term 中溯源
  • CHEBI 已就绪: 20,942 个已知化学物质，一旦获得药名即可匹配

P0：HP 症状同义词匹配增强

  • 目标: 利用 HP 同义词（19,348 条）改进 12 个未匹配症状
  • 当前: HP 同义词已解析但未用于匹配，可能漏掉 “Jaundice”/“Icterus” 这类同义关系

P1：无效关系引用修复

  • 现状: 116 条关系的 from 或 to 引用不存在的实体 ID
  • 影响: 关系有效性 99.93%，修复后 100%
  • 方式: 逐一检查缺失实体，补充或删除

P1：Unknown 实体分类

  • 现状: 31,447 实体中仍有 22,736 个 Unknown（72.3%）
  • 来源: 从关系提取的实体（Literature/MeSH 已有分类）
  • 方式: 利用 LLM 基于名称和上下文做类型推断

P2：症状-疾病关系自动增强

  • 方法: 利用 HP 的 phenotype → disease 关联，自动推断 has_symptom
  • 预期: 从当前 277 条扩展
  • 价值: 弥补临床关系仅占 0.18% 的不足

P2：Neo4j 导入

  • 目标: 将 enriched KG 导入图数据库
  • 前置: 需完成无效引用修复 + Unknown 实体分类

P2：CHEBI 跨库桥接

  • 目标: 利用 CHEBI 的 cross-reference 字段（CAS, KEGG, PubChem CID）
  • 价值: 与其他数据源建立化合物维度的跨库映射
