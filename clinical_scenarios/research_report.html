场景调研报告：肝病临床场景与知识图谱 Schema 设计

调研目的：为肝病知识图谱 v2.0 的 Schema 设计提供决策依据
调研方法：文献检索（PubMed, 199篇）+ 临床指南分析（AASLD/EASL/BCLC）+ 场景建模
报告时间：2026-04-27 GMT+8
版本：v0.2.0

摘要

本报告通过对肝病领域的系统调研（144个临床场景 + 199篇PubMed文献），验证了引入”临床场景层”作为知识图谱第三层的必要性和可行性。调研结论支持 Schema v2.0 扩展至少5个新实体类型和8个新关系类型，为从”文献为中心”的图谱向”临床可推理”的图谱演进提供了设计依据。

一、调研背景

1.1 存在的问题

当前知识图谱的 Schema 存在以下缺口：

问题表现影响
缺少临床语境只有实体和关系，没有”在什么情况下”无法做临床推理
文献占比过高99.82%的关系来自文献数据临床价值受限
实体类型单一仅Disease/Symptom/Drug/Literature/MeSH 5种表达力不足
Unknown实体22,736个 (99.46%) 待分类数据利用率低

1.2 解决思路

引入 “临床场景层”，作为连接实体层（L2）和文献关联层（L4）的桥梁：

无场景层： Disease ─ has_literature → Literature ─ has_mesh → MeSH
                           ↑ 这只是文献索引，不是临床知识

有场景层： Disease ─ hasClinicalScenario → Scenario ─ supportedBy → Literature
                           ↓                                          ↓
                    hasSymptom / hasComplication / hasScore     evidence_level
                           ↓
                    这就是临床可推理的知识

二、调研方法

2.1 肝病分类体系调研

参考标准：

  • ICD-10: 代码 K70-K77（肝病）
  • ICD-11: 代码 DA90-DD10（消化系统肝病）
  • AASLD 实践指南: 各肝病亚类的诊断标准
  • EASL 临床实践指南: 欧洲肝病协会的分类体系

2.2 临床场景定义方法

graph LR
    A[ICD分类框架] --> B[确定13大类]
    B --> C[每类细分亚类]
    C --> D[每亚类定义场景]
    D --> E[抽象维度模型]
    E --> F[场景校验]

2.3 文献检索策略

维度说明
数据库PubMed (MEDLINE)
时间范围2015-2026，偏重 2018-2026
检索方向15 个肝病相关方向
每方向检索数~15 篇
总计199 篇（去重后）
证据分级A（指南/共识）/ B（综述/Cochrane）/ C（队列研究）/ D（病例报告）

3.4 发现四：AliCoCo四层架构在医学领域可行

电商领域:  商品本体 → 商品概念 → 商业场景 → 用户行为
医学领域:  医学本体 → 医学概念 → 临床场景 → 文献关联
                ↓           ↓           ↓           ↓
           HepatoOntology  疾病/症状/  144个场景  175,328条
           分类体系       药物实例     (本实验)   文献关联

关键验证点：场景层(L3)的存在使得文献关联从”无序噪声”转变为”有语义线索的知识”。

3.5 发现五：Schema v2.0需要至少5个新实体和8个新关系

新增实体（从当前5种扩展到10+种）：

新实体必要性支撑证据优先级
Etiology (病因)49个病因驱动场景需要病毒/酒精/代谢/免疫/遗传P0
ClinicalScenario (场景)144个场景本身全场景需求P0
Complication (并发症)肝硬化场景需要SBP/HRS/HE/出血等P1
ClinicalScore (评分)量化评估需要MELD/BCLC/Child-PughP1
Treatment (治疗方案)治疗层级需要一线/二线/三线方案P2

新增关系（从当前4种扩展到12+种）：

新关系必要性示例
hasEtiology病因归属NAFLD → 代谢性病因
hasComplication并发症联系肝硬化 → SBP
hasClinicalScenario场景归属HCC → CS-HCC-02
hasScore评分关联肝硬化 → MELD 22
hasSeverity严重度标注CS-ALF-03 → 极危重
treatedByLine治疗层级HBV → 恩替卡韦(一线)
progressionTo进展关系NAFLD → NASH → 肝硬化
belongsToCategory场景分类CS-SL-01 → 脂肪性肝病

四、调研结论与建议

4.1 结论

  1. 临床场景层是必要的：7维模型已验证表达能力，能描述所有144个场景
  2. 现有Schema不足：5实体+4关系无法支撑临床推理
  3. 文献证据充分：大部分场景有A级指南支撑
  4. 扩展方案明确：5个新实体+8个新关系

4.3 风险与考量

风险影响缓解措施
扩展后图谱复杂度增加查询性能下降分层存储，场景层独立索引
新增实体数据源不明确填充困难实体抽取从文献+临床指南出发
场景定义未外部审核可能存在分类误差Andong审核 + 临床专家复核
国际指南vs中国临床差异场景适用性后续补充中文文献检索
