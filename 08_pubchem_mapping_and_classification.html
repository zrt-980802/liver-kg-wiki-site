关联数据处理：Unified v3 → v4 升级

1. 概述

本阶段完成了两项核心工作：

  1. PubChem CID 映射整合 — 将 13,390 个 ChEMBL→PubChem CID 映射写入 Unified 知识图谱
  2. ChEMBL 分子类型分类 — 基于 chembl_molecules.json 的 molecule_type 字段，为 v4 中所有 Drug 实体添加分子类型标注

两项工作使 Unified 知识图谱中的药物相关实体具备完整的小分子 vs 生物药分类体系，并为后续 STITCH 桥接奠定了基础。

2. 数据源

2.1 PubChem CID 映射（已完成）

  • 映射文件: cross_links/pubchem_mapping_state.json（13,390 条记录）
  • 失败记录: cross_links/pubchem_failed_names.json（50 条）
  • 方法: 通过 PubChem REST API 按药物名称查询 CID
  • 定时任务: Windows schtasks PubChemMapping（已完成，无需续跑）

2.2 ChEMBL 分子类型

  • 源文件: C:\Users\29557\HepatoOntology\drug_target_data\data\raw\chembl\chembl_molecules.json
  • 覆盖范围: 16,754 个分子（ChEMBL 数据库中的唯—药物分子）
  • 关键字段:
    • molecule_chembl_id: ChEMBL ID
    • pref_name: 首选名称
    • molecule_type: 分子类型分类（核心字段）
    • max_phase: 最高临床阶段
    • first_approval: 首次获批年份
    • drug: 是否被标记为药物

2.3 数据陷阱

⚠️ 关键理解: Unified v3/v4 中的 Drug 实体是药物-靶点机制记录对，而非唯一的药物实体。
52,589 条 Drug 实体来自 drug_mechanisms.json（188,000 条机制记录），
而 chembl_molecules.json 仅包含 16,754 个唯一药物分子。
因此 46,714 个 Drug 实体的 drug_chembl_id 在分子清单中无直接对应——这个剩余是正常的。

3. 处理流程

3.1 Unified v3：PubChem CID 整合

v2 (590MB) 
  │
  ├─ 读取 PubChem 映射 (13,390 条)
  ├─ 正则匹配 Drug 实体 (52,589 条)
  ├─ 按 drug_chembl_id 匹配 CID
  └─ v3 (560MB, 4,346 个实体新增 pubchem_cid)
  • 脚本: E:\shared\integrate_pubchem_to_v3.py
  • 耗时: ~6 秒
  • 内存: 流式写入，避免 590MB 全量内存加载

3.2 Unified v4：分子类型分类

v3 (560MB)
  │
  ├─ 读取 chembl_molecules.json (16,754 分子)
  ├─ 读取 PubChem 映射（补充未命中的 CID）
  ├─ 正则匹配 Drug 实体
  ├─ 按 drug_chembl_id 查 molecule_type
  ├─ 无匹配则保持原样
  └─ v4 (591MB, 5,875 个实体新增 molecule_type)
  • 脚本: E:\shared\classify_drugs_to_v4.py
  • 耗时: ~6 秒
  • 输出: 流式写入，590MB 文件仅单次完整读取

7. 与 STITCH 桥接的关系

PubChem CID 映射完成后，下一步是 STITCH 桥接（优先级 2）：

  • STITCH 数据格式: CIDs{N:08d}（如 PubChem CID 123 → CIDs00000123）
  • 映射链: ChEMBL ID → PubChem CID → STITCH CID → 药物互作数据
  • v4 中 4,346 个已标 CID 的实体可直接桥接
  • 12,713 个小分子药物均位于分子清单中，可进一步补充 CID

8. 已知限制

  1. 46,714 个未分类 Drug 实体: 这些实体的 drug_chembl_id 在 chembl_molecules.json 中不存在，属于 ChEMBL 药物-靶点机制数据中的额外药物记录。
  2. Failed 名称映射: 50 个药物名（以抗体和生物制品为主）在 PubChem 中不存在，需要单独处理（BiologicDrug 子类）。
  3. No entity-level classification: 每个 Drug 实体（药物-机制对）的 molecule_type 目前通过对同一 drug_chembl_id 的查询间接可知，但未显式标记到每个实体上（可以考虑后续按需补充）。
