证据链推理引擎 — 三层架构运行样例

端到端演示：HCC诊断场景下的三层模板架构协同工作
创建日期：2026-05-12

场景设定

一位患者，乙肝病史20年，体检发现AFP升高到 450 ng/mL，腹部超声发现肝脏有 3cm占位。医生想得到一份带证据链的诊断建议。

Layer 1: Meta-Template（元模板）

引擎识别出这是一个鉴别诊断场景，自动选择 DiagnosticAbduction_v1.0 模板。这个模板不包含任何医学知识，只定义了推理路径：

[ObservationParser] → [CandidateGenerator] → [DifferentialRanker]
         ↓                                       ↓
   提取临床观察                            初步排序候选疾病
         ↓                                       ↓
                              [EvidenceCollector] ← ← ← ← ← ← ┐
                                       ↓                      │
                              [EvidenceEvaluator]              │ 反馈边（证据不足时）
                                       ↓                      │
                              [InferenceEngine]                │
                                       ↓                      │
                              [ConflictResolution]             │
                                       ↓                      │
                              [ConclusionRanker]  → → → → → → ┘
                                       ↓
                              [ExplanationGenerator]
                                       ↓
                                 推理报告

关键：这9个节点本身不知道肝病、不知道AFP、不知道HCC——它只是一个通用的推理管道。

适用场景：所有需要鉴别诊断的临床场景（肝病、肿瘤、内科……）

Layer 3: Instance Template（实例模板）

运行时输入张三的具体数据，引擎动态查询知识图谱，填充实例：

输入: {observation: "AFP 450 ng/mL, 肝脏占位3cm, 乙肝病史20年"}

[ObservationParser]  → 结构化观察:
   {"afp": 450, "liver_mass": "3cm", "hbv_history": "20年"}

[CandidateGenerator] → 从KG查询肝病，生成候选:
   ├─ 肝细胞癌 (HCC)              ← 基线概率最高
   ├─ 肝内胆管癌 (ICC)
   ├─ 肝腺瘤
   └─ 肝转移瘤                    ← 低概率（无原发癌史）

[DifferentialRanker] → 初步排序:
   1. HCC (0.65)
   2. ICC (0.20)
   3. Hepatic adenoma (0.10)
   4. Metastatic tumor (0.05)

[EvidenceCollector] → 为每个候选收集多源证据:
   ┌─ HCC:
   │   ├─ 本体证据: HCC ⊂ LiverCancer (DOID:684)
   │   ├─ 关联证据: AFP↑ → HCC (置信度0.85, PMID: 34567890)
   │   ├─ 文献证据: "AFP >400对HCC诊断敏感度约80%" (PMID: 35689319)
   │   └─ 时序证据: HBV→肝硬化→HCC（标准病程）
   │
   ├─ ICC:
   │   ├─ 本体证据: ICC ⊂ LiverCancer (DOID:4915)
   │   ├─ 关联证据: CA19-9↑ → ICC (置信度0.70)
   │   └─ 缺:AFP飙升与ICC关联弱
   │
   └─ Hepatic adenoma:
       ├─ 本体证据: Hepatic Adenoma ⊂ LiverBenign (DOID:0050868)
       └─ 缺: 男性+HCC风险因素+AFP>400不支持腺瘤

[EvidenceEvaluator] → 评估证据质量和冲突:
   ├─ HCC: 证据充分 (4/4维度)，置信度0.85 ✅
   ├─ ICC: 证据不足 (2/4维度)，需要CA19-9数据 ⚠️
   └─ Adenoma: 证据矛盾 (AFP>400不合理) ❌

[InferenceEngine] → 加权融合:
   ├─ HCC:       0.75 × 0.85 = 0.64  ← 最高
   ├─ ICC:       0.20 × 0.50 = 0.10
   ├─ Adenoma:   0.10 × 0.20 = 0.02
   └─ Metastatic: 0.05 × 0.30 = 0.015

[ConclusionRanker] → 最终排序:
   1. HCC (0.64) — 强烈支持
   2. ICC (0.10) — 低概率，建议查CA19-9
   3. Hepatic adenoma (0.02) — 极低概率
   4. Metastatic tumor (0.015) — 极低概率

[ExplanationGenerator] → 生成推理报告（见下方）

最终输出：推理报告

三层分工一览

层角色都知道什么都不知道什么
Layer 1推理管道的建筑师推理的步骤和顺序AFP、HCC、患者
Layer 2肝病专家顾问肝癌怎么诊断、查什么证据张三的具体情况
Layer 3张三的主治医生张三的所有检查结果和病史推理本身怎么运行

设计价值

可复用性：要新增一个”脂肪肝评估”场景，你不需要重新设计推理管道（Layer 1保持不变），只需要写一份新的Layer 2配置（NAFLD Domain Profile），然后接收不同的Layer 3患者数据。

可解释性：每一层都能独立输出log，审计时可追溯”这个结论是哪个模板、哪个配置、哪条证据产生的”。

可扩展性：新的数据源（如文献数据库、EHR系统）只需在Layer 2配置中新增一个evidence维度，Layer 1的管道无需变更。
