Layer 3 推理执行引擎：执行计划

此计划针对修订后的 v2.0 任务要求制定 策略：MVP-0 先行，数据驱动，逐层扩展 核心原则：不假设任何表存在，先审计现有数据库，再决定引擎能做什么 创建日期：2026-05-11 状态：📋 计划就绪，待启动

第一阶段：数据库审计与 MVP-0 定义（Day 1）

目标

明确现有 SQLite 能支撑什么，定义”最小可运行子集”。

具体任务

序号任务产出验收标准
1.1导出 SQLite 完整 schemaaudit/db_schema_dump.sql包含所有 CREATE TABLE 语句
1.2列出 Layer 2 HCC 配置中引用的所有查询模板audit/hcc_queries_inventory.md每个查询标注来源插件槽
1.3逐一对照：查询模板表/字段 vs 实际存在的表/字段audit/data_source_availability_matrix.md三色标注：✅/🚧/❌
1.4定义 MVP-0：只基于现有表，跳过 ObservationParseraudit/mvp0_definition.md明确输入格式、使用的表、预期输出

关键决策

决策1：ObservationParser 是否纳入 MVP-0？

→ 选 B：跳过。直接传入结构化观察 {observation_id: "afp_elevation", value: 520}，ObservationParser 在 MVP-1 实现。

决策2：证据维度哪些纳入 MVP-0？

维度现有表支撑MVP-0 决策
literature❌ 无 PubMed 数据跳过（维度标记 unavailable）
ontology✅ entities 表有类型信息纳入（简化：is-a 关系查询）
association✅ edges + edge_semantic_facets核心纳入
clinical❌ 无 EHR 数据跳过（维度标记 unavailable）

MVP-0 结论：引擎只使用 ontology + association 两个维度，验证加权融合和输出报告。

第二阶段：运行时数据结构设计（Day 1-2）

目标

定义引擎内部流转的数据模型，确保可序列化、可复现。

具体任务

序号任务产出验收标准
2.1设计 Session 结构（含上下文缓存机制）schemas/instance_data_schema.md §A可 JSON 序列化，含完整 provenance
2.2设计 ExecutionPlan 结构（含反馈边处理）同上 §B支持拓扑排序 + 条件回退
2.3设计 StepResult 结构（含错误处理）同上 §C支持缓存复用、错误降级
2.4设计 InferenceResult 结构同上 §D字段与 Layer 1 输出 Schema 一一对应
2.5定义数据结构的 JSON Schemaschemas/instance_data_schema.json可通过 jsonschema 验证

关键决策

决策3：上下文缓存粒度

→ 选 A：全量缓存。每个 StepResult 完整存储。医疗推理需要可复现性，牺牲内存换确定性。

第三阶段：最小引擎实现（Day 2-4）

目标

实现可运行的 MVP-0 引擎，验证端到端流程。

具体任务

序号任务产出验收标准
3.1实现配置加载器（YAML 解析 + 继承 + 预编译）engine/config_loader.py加载 HCC 配置，继承生效
3.2实现 DAG 调度器（拓扑排序 + 状态管理）engine/dag_scheduler.py对 DiagnosticAbduction DAG 正确排序
3.3实现节点执行器基类 + 具体实现engine/node_executors/各节点可执行（除 ObservationParser）
3.4实现查询编译器（SQL 模板 → 参数绑定）engine/query_compiler.py将 SQL 模板编译为 SQLite 执行语句
3.5实现结果转换器（DB 行 → EvidenceFacet）engine/result_transformer.py按 attribute_mapping 转换字段
3.6实现 MVP-0 端到端推理tests/test_mvp0_end_to_end.py输入结构化观察，输出完整推理报告

节点执行器实现优先级

节点MVP-0 实现说明
ObservationParser跳过/透传直接输入结构化观察
CandidateGenerator✅ 规则驱动基于 ontology_driven 遍历 entities 表类型
DifferentialRanker✅ 简化只按 base_probability 排序，无鉴别矩阵
EvidenceCollector✅ 核心查询 edges + edge_semantic_facets
EvidenceEvaluator✅ 简化只检查 normalized_confidence 阈值
InferenceEngine✅ 核心加权融合（ontology + association 权重）
ConflictResolution跳过MVP-0 假设无冲突
ConclusionRanker✅ 简化按 confidence 排序
ExplanationGenerator✅ 核心输出 JSON 格式报告

风险预案

风险触发条件应对策略
现有表无法支撑有意义推理edge_semantic_facets 为空或结构不匹配使用 mock 数据填充表，验证引擎结构
Layer 2 SQL 模板语法错误查询编译失败ConfigLoader 中增加 SQL 语法预检
反馈边导致无限循环条件判断或 max_iterations 失效设置全局超时（30s），强制终止
TESG 接口过早设计TESG agent 产出延迟只实现 Level 2 降级，TESG 接口留空
并行在 SQLite 上无收益10 个串行推理耗时 > 10 倍单次架构预留接口，实际限制并发数 1
